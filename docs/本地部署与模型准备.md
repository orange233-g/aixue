# 本地部署与向量模型准备

本文说明如何在本地把 ai学（Aixue）跑起来，以及如何准备知识库语义检索所需的**内置向量模型**。

## 1. 环境要求

| 项 | 要求 |
|---|---|
| Node.js | 20.19+ 或 22.12+（Vite 8 引擎要求；本项目开发使用 Node 24） |
| npm | 10 及以上 |
| 浏览器 | Chrome / Edge 等 Chromium 内核浏览器（端侧推理需要 WebAssembly SIMD 与 SharedArrayBuffer） |
| Android 构建（可选） | JDK 17+、Android SDK（compileSdk 36）——见 [ANDROID_RELEASE.md](ANDROID_RELEASE.md) |

## 2. 安装与启动

```bash
npm ci                                          # 按 package-lock.json 安装依赖
npm run dev                                     # 开发服务器（默认 5173）
npm run dev -- --host 127.0.0.1 --port 5174     # 指定 host/端口
npm run build                                   # 生产构建 → dist/
npm run preview                                 # 本地预览生产产物
```

`dev` 与 `build` 会先执行 `scripts/copy-ort.mjs`，把 onnxruntime-web 的 wasm 后端复制到 `src/assets/ort-wasm/`（构建产物，不入库）。若提示缺少文件，说明 `node_modules/onnxruntime-web` 未安装完整，重新 `npm ci` 即可。

### 端口与数据隔离

不同端口属于不同**站点来源**，IndexedDB 与 LocalStorage 互不共享。换端口后看不到之前的数据是正常现象，不是数据丢失；需要同一份数据就固定使用同一个端口。

### 开发环境的两个中间件（生产构建不包含）

- `/__ai`：浏览器直连厂商 API 会被 CORS 拦截，dev server 代转请求。目标地址需命中厂商网关 host 精确白名单（由 `src/ai/providers/manifest.ts` 推导），内网/环回/裸 IP 一律拒绝；可用环境变量 `AI_PROXY_ALLOW_HOSTS`（逗号分隔的精确 host）追加自定义网关。
- `/__log` 与 `/__genlog`：把页面日志与生题原文写入项目目录的 `logs/`（`run.log`、`run-gen.log`），便于本地排障。该目录已在 `.gitignore` 中排除，其中可能包含你的测试内容与模型输出原文，**不要提交**。

此外 dev server 会给页面补 `Cross-Origin-Opener-Policy` / `Cross-Origin-Embedder-Policy` 响应头，使页面处于 cross-origin isolated 状态——这是 onnxruntime-web 的 SIMD-threaded wasm 后端使用 `SharedArrayBuffer` 的前提，缺少该头会导致「本地推理引擎加载失败」。

## 3. 配置 AI 模型（生题/聊天必需）

生题与聊天需要你自己的模型服务：

1. 打开应用「我的 → AI 设置」；
2. 选择供应商（内置 DeepSeek、智谱 AI、腾讯混元、Kimi、MiniMax、OpenAI 兼容、小米 MiMo、火山方舟、通义千问），填入 API Key；
3. 点「获取模型列表」选择模型，或手动填写模型名；可点「测试连通」验证；
4. 保存后在生成页即可使用。

API Key 只保存在本机 IndexedDB。使用预置厂商之外的服务时，可填写自定义 API 地址（保存前会校验协议与主机，并提示 Key 的发送目标）；开发环境下还需把该网关 host 加入 `AI_PROXY_ALLOW_HOSTS`。

## 4. 向量模型（知识库语义检索）

知识库有两种检索方式：

| 检索方式 | 是否需要模型 | 说明 |
|---|---|---|
| BM25 关键词检索 | 不需要 | 建库时直接选择即可；基于词频统计，适合关键词明确的资料 |
| 向量语义检索 | 需要 | 建库时选择内置 bge 或已导入的模型；建索引后按语义召回 |

### 4.1 内置模型（bge）

`bge-small-zh-v1.5`（约 90 MB，MIT）随 app 分发：文件放在 `public/models/bge/`，构建时复制到 `dist/` 并随 APK 打包。
首次建索引/检索时，应用会把它复制到本机 IndexedDB（`ai-embed-files`），之后直接复用；不再被任何知识库绑定时自动释放。
文件清单、字节数与 SHA256 记录在 [src/ai/embed/registry.ts](../src/ai/embed/registry.ts)。

### 4.2 导入模型（可选，例如 Qwen3-Embedding-0.6B）

体积较大的模型不随 app 分发，改为「发布页下载 → 应用内导入」：

1. 从发布页（GitHub Releases）下载 `qwen3-embedding-0.6b.aixue-model`；
2. 应用内「我的 → 向量模型 → 添加模型」，选择该文件；
3. 导入会校验 manifest、文件大小与 SHA256，成功后即可在建库时选用；模型文件只保存在本机，可随时删除。

模型包格式、打包与发布步骤见 [模型包与导入.md](模型包与导入.md)。

### 4.3 运行时行为

- **内置模型首次使用时自动准备**：选中 bge 建库/生成索引/推理时，应用会从 `/models/bge/…` 读取文件并缓存到 IndexedDB，之后直接复用。
- **导入模型**：导入时已写入本机并校验 SHA256；文件缺失（被清理/清数据）时会提示重新导入。
- **自动释放**：删除知识库或启动应用时，会清理「没有任何知识库绑定」的**内置**模型缓存；导入模型不自动清理，只能显式删除。
- **失败表现**：模型缺失、加载失败或推理环境不满足（例如浏览器不支持 SharedArrayBuffer）时，知识库会提示失败并可重试，不会伪装成"可用语义检索"。

## 6. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 换端口后数据"消失" | 不同端口是不同 origin，数据不共享；固定用同一个端口，或用应用内的数据备份/恢复迁移 |
| 「获取模型列表」报网络错误（开发环境） | 该厂商网关 host 未命中代理白名单；把 host 加入 `AI_PROXY_ALLOW_HOSTS` 后重启 dev server |
| 知识库提示「本地推理引擎加载失败」 | 页面未处于 cross-origin isolated（缺少 COOP/COEP 头）或 wasm 后端缺失；确认通过 `npm run dev` 启动（dev server 会自动补头）且 `src/assets/ort-wasm/` 已生成 |
| 首次向量检索等待较久 | 首次需要加载/缓存模型权重（bge ≈ 90 MB、Qwen3 ≈ 596 MB），属正常；缓存后明显变快 |
| 页面改了没变化 | dev server 对 HTML/JS/CSS 返回 no-store，理论上不会缓存；若异常请硬刷新并确认 dev server 未重启失败 |
