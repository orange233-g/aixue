# 知识库：索引建立与检索选择规则说明

> 本文档说明「ai学」知识库从**建库 → 建索引 → 引用检索 → 注入生成**的完整机制，配套
> 代码可对照查阅。文档与代码约定一致，数值均取自定义常量，改动代码请同步本说明。
>
> 涉及文件：`src/services/kb/embed.ts`（锚点/索引策略）、`src/services/kb/ref.ts`（引用检索）、
> `src/services/kb/search.ts`（BM25/向量检索原语）、`src/services/kb/scope.ts`(范围切卷)、
> `src/stores/useKBStore.ts`（建库/生成索引流程）。

---

## 0. 一句话总览

知识库先在本地把源文件切块清洗（**零 token**），再建**两种索引**可相互配合：

- **关键词 BM25 索引**：任何规模都建，本地离线；
- **语义向量索引**（bge/Qwen3）：按正文规模**自适应**选「全量」或「节采样」，受 4000 锚点预算约束。

引用时**按用户意图**在「章号指令 / 向量+BM25 融合 / 关键词降级」三条通道里选一套，把最相关的
章节（≤2800 字）注入；出题还给「范围切卷（每卷≤4500 字）」。

## 1. 建库流程（先做什么）

```
源文件解析 → 原文切片(raw层) → 结构感知分块(清洗工作层) → 本地 BM25 索引 → 落 IndexedDB
```

- **raw 切片层**：源文本按段落切片，保留 span 偏移可回源。
- **清洗工作层**：碎行合并（仅对检测到碎行特征的文件启用），只动换行/空行、不改字。
- **分块策略**：目标 800 字/块（最小 300、最大 1500），按标题/代码块/空行找断点；块数 ≈ 总字数 ÷ 800。
- **bodyText / sections**：`bodyText` = 清洗后正文字符串；`sections` = 切块数组（`{id,title,start,end,file}`）。
  **正文总字数 = `charCount = bodyText.length`** 是后面选索引策略的决定量。

> 注：此处的 `sections`（检索分块）与阅读器目录统计的真实章节是**两个口径**，卡片「章节」数按真实结构
> 统计，检索则用 `sections` 切块。

## 2. 建立索引的方式 —— 多少字分别选什么（核心）

建索引进到**「规模自适应锚定」**（`embed.ts`）。向量化的是**锚点**（检索定位用的小单元），不是整段正文。
锚点策略按正文总字数由 `decideAnchorStrategy(charCount)` 自动决定：

```
fullNeeded = ceil(charCount / 300)          // 全量模式所需锚点数
full 当且仅当 fullNeeded ≤ 4000             // 否则 section
```

**阈值换算：300 × 4000 = 1,200,000 字 = 120 万字。**

| 正文规模 | 语义索引方式 | 锚点粒度 | 特点 |
|---|---|---|---|
| **≤ 120 万字** | **full 全量**：每节内按 **300 字**切 chunk 向量化，首 chunk 带节标题 | 每 chunk 1 个向量点，正全文覆盖 | 节中后部内容也能被向量捞到，检索最细 |
| **> 120 万字** | **section 节采样**：每节 1 个节首锚点（**200 字**+标题）；长节（**>2000 字**）追加 1 个中段锚点（节中点起 200 字） | 每节 1–2 个向量点，定位到"节" | 控成本、省时省内存，够用 |

### 关键常量（已同步代码）

| 常量 | 值 | 含义 |
|---|---|---|
| `CHUNK_CHARS` | 300 | full 模式每个 chunk 字符数 |
| `ANCHOR_HEAD_CHARS` | 200 | section 模式节首锚点截取字符数 |
| `ANCHOR_BUDGET` | 4000 | 锚点预算 ≈ 真机 2–3 分钟可接受的索引量 |
| 长节阈值 | 2000 | section 模式下超过则追加中段锚点 |

### 别忘了 BM25 这层

`BM25 关键词索引` 对**所有库、任何规模都建**（本地、零 token）、不参与上述分档。也就是「关键词检索」
永远可用，是语义索引的兜底。

### 检索怎么把"锚点"还原成内容

不管 full 还是 section，命中后用 `anchorSectionIdx` 把**锚点下标映射回所属"节"**，再按 `sections[i].[start,end)`
从 `bodyText` 取**整节正文**（整批截到 2800 字）注入。所以 section 虽只向量化了节首 200 字当"探针"，
定位到的仍是完整一节。

### 模型切换与降级

全局检索模型 `embed.modelId` 可切：`bm25`（不建向量，纯关键词）/ 内置 `bge` / 用户导入的模型（如 `qwen3`）。
- 只有选了向量模型（bge 或已导入模型）才会建向量索引；
- **切换模型后，旧模型算的索引作废，需重新生成**；
- 使用向量前提：该库 `embedStatus='ready'`、向量数 == `sections.length`、且向量 `modelId` == 当前模型，否则降到 BM25。

## 3. 引用时的检索选择规则（`buildKbRef` 通道）

引用知识库（聊天 / 出题引用）发送时，`buildKbRef`（多库则 `buildMultiKbRef` 逐库叠加、空行分隔）
把选中内容拼成「【知识库·XXX 参考资料】」块，受 **2800 字**（`KB_REF_CAP`）上限约束。

### 通道① 章号指令（query 点名要哪章）

- query 形如「第 N 章 / 第 N-M 章」→ `parseChapterRange` + `resolveChapterSections` **精确取章**，不模糊检索；
- 整体截到 2800 字注入；章号超界定位为空 → 回退语义通道。

### 通道② 向量 + BM25 RRF 融合（默认、最常用）

| 步骤 | 规则 |
|---|---|
| 前置闸 | 有向量缓存、向量数==节数、当前模型非 `bm25` 且 == 库向量 `modelId`（否则降级） |
| 双路召回 | ① BM25 关键词取 top **12**（`topK*2`）；② query 向量化（Qwen3 加 `Instruct:` 前缀）后取 **top 12** 余弦近邻 |
| **相关性门禁** | 若 **BM25 零命中** 且 top1 锚点余弦 **< 0.5**（`MIN_EMBED_COS`）→ 判定库里没有相关内容，返回空、提示未找到。阈值由评估定标（正例≥0.509 / 负例≤0.454），防负例 query 硬凑 topK、防 AI 东拼西凑 |
| **RRF 融合** | 两路命中按 Reciprocal Rank Fusion 合并（向量锚点经"锚点→节"映射去重保序），取 **top 6**（`KB_REF_TOPK`） |
| 组装截断 | 每条拼「## 标题 + 正文」，整批 `withCap` 截到 **2800 字**，超长标注「已截断：仅含前 n/m 字」 |

### 通道③ 降级纯 BM25（关键词模式）

无向量缓存 / 模型不一致 / query 向量化抛错 → 退化为纯 BM25 关键词检索。

### 门禁拒绝 → 空

返回「未在知识库中找到相关内容」提示块，配合 prompt 纪律"没有就说没有"，不脑补。

> 每一项检索命中都会写一条 `scope=kb` 运行日志（`知识库引用·命中/未命中（通道名）`），
> 含 `query/channel/hits[{i,title,score,file}]`，方便对照本次实际走了哪条通道、命中哪些节。

### 关键参数速查

| 参数 | 值 | 含义 |
|---|---|---|
| `KB_REF_TOPK` | 6 | 每次检索召回章节数 |
| `KB_REF_CAP` | 2800 | 引用注入字符上限（≈2500–3500 token） |
| `MIN_EMBED_COS` | 0.5 | 相关性门禁余弦阈值 |
| BM25 候选 | topK×2=12 | 参与融合前关键词候选数 |

## 4. 范围选择与出题切卷（`scope.ts`）

出题（生成题目）**不走** `buildKbRef` 的 topK 检索，而是走**范围切卷**：

- 引用库可勾选章节（选择范围弹层）；
- `planVolumes` 把选中的 `sections` 按**文档序**装箱成 ≤**4500 字/卷**（`VOLUME_BUDGET`），每卷一次生成请求；
- **空选择 = 该库全部内容**（D7 语义），且「确定」需至少 1 节；
- 单节超预算按空行→句末标点硬切多卷；勾选不连续时自动闭合前卷，不带进未选内容。

| 场景 | 走哪条 | 取多少 | 注入量 |
|---|---|---|---|
| 问剧情 / 聊天（引用） | 通道② 向量+BM25 / ③ 降级 BM25 | top 6 节 | ≤2800 字 |
| 明确说"第 N 章" | 通道① 章号指令 | 指定章 | ≤2800 字 |
| 出题（引用 + 选范围） | 范围切卷 `planVolumes` | 勾选节 | 每卷 ≤4500 字逐卷生成 |
| 库里没有相关内容 | 门禁拒绝 | 0 | 返回「未找到」提示块 |

## 5. 切换 / 排障速览

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 明明升级了语义检索，日志却显示「关键词BM25」 | 向量缓存未预热 / 切换模型未重建 / 向量数≠节数 | `warmVectorCache` 预热；重新生成索引；确认当前检索模型与库一致 |
| 点「升级为语义检索」报「本地推理引擎加载失败」 | onnxruntime 后端加载失败（wasm 路径 / cross-origin isolation） | 见 `docs/app_bug.md` 6.47 |
| 「选择范围」无法取消全选 | 「全选」是开关，全选下显示「取消全选」 | 直接点该按钮清空 |
| 大库索引疑似缺失部分内容 | section 模式只采样节首/中段做锚点 | 属预期（定位到节，仍取整节正文）；如需更高覆盖重建为 full（小库自动） |

## 6. 实测验证（以「凡人」库为例，2026-08-26）

从应用 IndexedDB 实读 + 用 `embed.ts` 公式复算，结果完全一致：

| 指标 | 值 | 判定 |
|---|---|---|
| 正文总字数 `charCount` | 4,774,408（约 477 万） | — |
| 检索分块数 `sectionsLen` | 5059 | — |
| `fullNeeded = ceil(4774408/300)` | 15915 | 远超预算 4000（margin 11915） |
| **`decideStrategy`** | **`section`（节采样）** | >120 万字 |
| 复算锚点数（每节1 + >2000字加1） | 5059 | — |
| 实测存储锚点数 `vec.vectors.length` | **5059** | 与复算一致 |
| `anchorSectionIdx.length` | 5059 | 与锚点数一致 |
| 向量模型 / 维度 | bge-small-zh-v1.5 / 512 | — |
| `embedStatus` | `ready` | — |

**结论**：凡人库约 477 万字（远大于 120 万阈值），实际走 **section 节采样**；且所有分块均 ≤2000 字，
每节仅 1 个节首锚点，**共 5059 个锚点**（锚点数=节数，未触发"模型不一致/向量数≠节数"的降级条件），
语义检索当前可正常使用。
